Game Picker Library

A rebuild of "Add Games to Category" in the App Picker's grid style. Each console gets its own shelf, and every game is drawn with its own icon display mode, so mixed covers, discs, cartridges and ICON0 tiles stand side by side on one ledge. All colors come from deriveStorefrontColors() on the chosen theme, so switch presets below to check each one.

Click the screen, then use ←↑↓→ to move, Enter for A, Q/E for L1/R1, Y for a whole shelf, X to change the view, S for Done and Esc for Cancel. Tiles can also be clicked.

What changes

Today

  • A checkbox list of collapsed platform headers with nested title rows.
  • Hardcoded purple and grey (0xFF574DDB, 0xFFC9C7E8) that ignore the theme.
  • Up and down only. Long libraries take dozens of presses to cross.
  • No artwork, so similar titles are hard to tell apart.

Proposed

  • Shelf rail on the left: In RPGs first, then one shelf per console, then Memory Cards.
  • A 6-column art grid for the current shelf. Tiles sit on a ledge line so mixed shapes share a baseline.
  • Each tile uses the game's resolved IconDisplayMode: per-game, then per-console, then global.
  • The header counts what will be added and removed, matching what confirmGamePicker actually does.

Color roles

Nothing on the screen uses a literal color except the removal mark, which takes the existing destructive role. Preset themes resolve their accent to white, so the hue comes from the wave, the same way the App Drawer and App Picker get it.

Search is left out of the first pass on purpose, because CHANGE_SORT is already taken by the view toggle. If search is wanted, it can be given the App Picker's header entry for touch, plus a long-press on Y.

Build plan

  1. State. Replace the flat selectedItemId list in GamePickerState with shelves, shelfIndex, focusZone (Rail or Grid), a focusedIndex per shelf, and viewOverride: IconDisplayMode?. Remove the expanded-state map. Keep the selection sets and prepare() / clearSelection() semantics as they are.
  2. Pure logic. Add a GamePickerLogic.kt next to AppPickerLogic.kt: build shelves, move in the rail and grid with the shared gridMove, toggle a whole shelf, and compute adds and removals. Add a GAME_PICKER_GRID_COLUMNS = 6 constant and unit-test it the same way as AppPickerLogicTest.
  3. Icon at picker size. GameIcon needs an XMBItem and has a private NATURAL_ART_HEIGHT = 84.dp. Add an artHeight parameter (defaulting to the current value) and a small Game → XMBItem adapter, so the picker reuses resolveIconDisplay and every fallback without duplicating them. When the view is overridden, pass a single-mode map instead of the user's settings.
  4. Screen. Rewrite GamePickerScreen on deriveStorefrontColors(), reusing the App Picker's header, focus layers, PfpCheckBadge, footer ControllerPromptBar and the touch reconciliation from AppPickerGrid. Add ShelfRail, ShelfLedge (the row line plus an 8dp shadow), and MemoryCardTile.
  5. Wiring. Route LEFT, RIGHT, PREV/NEXT_CATEGORY and CHANGE_SORT through pendingGamePickerAction in XMBViewModel, which forwards only UP, DOWN, SELECT, OPEN_CONTEXT_MENU, BACK and HOME today. Add menu sounds for shelf changes and toggles.
  6. Performance. One LazyVerticalGrid per shelf, keyed by game id. Libraries with 2,000+ ROMs only lay out the visible rows. Artwork loads through the existing Coil cache. Shelf counts are derived and never stored.
  7. Checks. Logic tests for nav edges, empty shelves, a shelf shrinking under the cursor, and adds and removals. Add a screenshot pass on Classic Blue, Silver and Golden Amber, since those two pale presets flip the palette to dark text.

Open questions

  • Should the In RPGs shelf list only games that are already in the category, or also the games checked during this visit?
  • Should consoles that have no games still show as shelves, greyed out, or stay hidden as they are now?
  • Should the X view choice be remembered between picker visits for the rest of the session?
